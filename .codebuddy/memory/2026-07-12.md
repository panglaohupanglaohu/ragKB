## Agent 朝一个方向跑的真正根因：edge→courier 联动
- 用户反馈：硬刷后 agent 还是朝一个方向跑，"不是演练造成的，而是团队之间 agent 关系带来的"
- 真正根因找到了：`office-scene.js` 的 courier（递文件）循环只排除 `broadcast`，eco 的 `signal_food`/`signal_help`/`signal_court`/`mate`/`predator` 边全都会触发 courier 动画
  - eco 回放每一帧每个 creature 发 FOOD/HELP/COURT 信号 → 创建 edge → courier 循环让发信号者真的走过去"递文件"
  - 多个 agent 的信号目标指向同一个 peer（pickPeer bug）→ 全员朝那个 peer 跑
- 修复1（office-scene.js）：courier 循环跳过 `signal_food`/`signal_help`/`signal_court`/`mate`/`predator` 边，只画弧线不触发递文件
- 修复2（eco-replay.js）：`shared_to` 原本派 `step(offer_help)` 创建 `help` 边会触发 courier，改用 `eco_signal(help)` 只画弧线
- 之前修的 `pickPeer` 随机化和 `noBreaks` 字段都是对的但不够——courier 联动才是 agent 物理移动的真正来源

## usage.db 损坏修复
- 现象：后端启动报 `sqlite3.DatabaseError: file is not a database`（budget/store.py:25）
- 根因：`storage/usage.db` 文件头是 `HTTP/1.1 200 OK`——某个 HTTP 响应体被错误写入了这个文件（应该是某次 curl 或 fetch 误写到 SQLite 路径）
- 修复：删除损坏的 usage.db，SQLite 会在下次连接时自动重建空表
- 注意：这会丢失历史 token 用量统计，但不影响功能运行
