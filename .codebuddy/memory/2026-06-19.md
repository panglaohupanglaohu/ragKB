## LLM 配置重启丢失修复
- **根因1**: `_init_harness_from_teams` 只找第一个有 key 的 default 模型同步到全局 harness，若用户保存 key 的模型不是第一个团队或不是 default，重启后 harness 拿不到 key
- **根因2**: `settings.json` 的 `llm.api_key` 为空，`from_settings_file` 创建的 harness 无 key，而 model_pool 的 key 只存到 `.api_keys.json`
- **修复**:
  - `_init_harness_from_teams`: 两轮查找 — 第一轮找有 key 的 default 模型；若无，第二轮找任意有 key 的模型
  - `update_llm_provider` + `update_model`: 保存 key 时同时写入 `settings.json` 的 `llm` 段，确保 `from_settings_file` 重启后能读到
  - `update_model`: default 模型有 key 时也持久化到 settings.json

## API Key 加密存储读取修复（真正根因）
- **根因**: `secret_store.py` 把 `.api_keys.json` 加密成 `{"__encrypted__": true, "ciphertext": "..."}` 格式，但 `api.py::_load_api_keys()` 直接 `json.load` 读取，不解密 → 重启后所有 model api_key 读不回来 → harness 无 key → 测试连接失败
- **修复**:
  - `_load_api_keys()`: 改用 `secret_store.load_model_api_keys()` 解密读取
  - `_save_model_pool()`: 改用 `secret_store.save_model_api_keys()` 加密保存
- 验证: `load_model_api_keys()` 能正确解密 `build_system/codebuddy` 的 key
