# 全仓库分阶段重构路线

## 总原则

- 先收口验证体系，再清临时代码，再拆核心巨石；不要先大规模重构核心路径。
- 每个阶段只处理一个风险面，能用测试或脚本证明完成。
- 不删除运行时数据、模型配置、团队状态、密钥配置和历史兼容入口，除非先有替代路径和回归验证。
- 当前已知核心路径：`src/backend/main.py`、`src/backend/agents/api.py`、`src/backend/agents/chat_harness.py`、`src/backend/agents/team_manager.py`、`src/backend/agents/team_store.py`、`src/backend/agents/models.py`、`src/backend/agent_team_api.py`、`src/backend/agents/plaza_routes.py`、`src/backend/agents/plaza_engine.py`、`src/backend/sandbox/api.py`、`src/backend/sandbox/trial_api.py`、`src/frontend/js/agent-team-config.js`、`src/frontend/js/plaza.js`、`src/frontend/js/skill-extract.js`、`src/frontend/js/cost-dashboard.js`、`src/frontend/js/digital-twin-cli.js`。

## Phase 1：建立基线与可执行验证入口

**阶段目标**

- 统一本仓库的最低验证命令，先解决“怎么判断没改坏”的问题。
- 明确 `rtk` 依赖、Windows `venv`、前后端测试入口、文档签名检查的可用状态。

**允许修改的范围**

- `package.json` scripts。
- `scripts/` 下新增只读验证脚本或修复现有验证脚本参数。
- `README.md` 或新增 `docs/` 验证说明文档。
- `pyproject.toml` 的 pytest 配置，仅限让现有测试入口可稳定收集。

**明确不允许修改的范围**

- 不改业务代码：`src/backend/agents/**`、`src/backend/sandbox/**`、`src/frontend/js/**`。
- 不改 `config/*.json` 的真实模型、团队、密钥配置。
- 不删除现有测试。

**验证方式**

- `.\venv\Scripts\python.exe -m pytest --collect-only -q`
- `.\venv\Scripts\python.exe -m compileall -q src/backend`
- `npx vitest run --run`
- `node scripts/check-docs-signoff.cjs --strict`
- `npm run build`

**风险点**

- `package.json` 当前脚本依赖 `rtk`，但本机可能没有 `rtk`。
- 后端测试分散在 `tests/` 和 `src/backend/tests/`，部分测试可能依赖活服务或历史符号。
- `docs/` 签名规则已存在，但 27 个文档不满足 strict。

**完成标准**

- 有一套本机可复制的验证命令，能区分“必须通过”和“已知失败”。
- 已知失败写入文档，包含失败文件、原因、是否阻断重构。
- CI 或本机脚本不再依赖未安装的 `rtk` 作为唯一入口。

**建议的 commit 粒度**

- commit 1：验证脚本和 npm scripts 收口。
- commit 2：记录 baseline 结果和已知失败清单。

## Phase 2：清理显性临时代码与仓库杂物

**阶段目标**

- 清理确认无运行依赖的临时文件、备份文件、误提交文件，降低仓库噪声。
- 先处理低风险、可回滚、与核心代码无耦合的对象。

**允许修改的范围**

- `.gitignore`。
- 已跟踪但明显为临时产物的文件，例如 `.perm_test_5`、`tests/_test_patch_temp.py`、`tests/_test_write_temp.txt`、`src/backend/0tfuaiyp`。
- `_temp/design-demos/*.html`，仅在确认不被文档或构建引用后移除或迁移到归档目录。
- `README.backup-20260618T235918Z.md`、`README.html`，仅在确认不是发布产物后归档或删除。

**明确不允许修改的范围**

- 不删除 `storage/`、`config/`、`node_modules/`、`venv/` 中的本地运行状态。
- 不删除 `ponytail/`，它是独立子项目，不属于临时目录。
- 不删除任何被 `vite.config.mjs`、`start.ps1`、`main.py` 直接引用的文件。

**验证方式**

- `git ls-files` 确认清理对象均为显性临时或归档文件。
- `rg "0tfuaiyp|_test_patch_temp|_test_write_temp|README.backup|README.html|design-demos" .`
- `npm run build`
- `.\venv\Scripts\python.exe -m compileall -q src/backend`

**风险点**

- `_temp/design-demos` 可能是设计过程证据，不应无确认硬删。
- `README.html` 可能被人工当作静态发布物使用。

**完成标准**

- 临时文件从 tracked 文件中移除或转入明确归档位置。
- `.gitignore` 能防止同类测试残留再次进入版本库。
- 构建和编译不受影响。

**建议的 commit 粒度**

- commit 1：清理测试残留和误提交文件。
- commit 2：处理 README 备份/HTML 与设计 demo 归档。
- commit 3：补 `.gitignore` 规则。

## Phase 3：文档去重、签名与事实对齐

**阶段目标**

- 解决文档过期、重复、互相矛盾的问题。
- 建立“README 是入口，docs 是决策历史，API 以代码/OpenAPI 为准”的规则。

**允许修改的范围**

- `README.md`。
- `docs/*.md`。
- `docs/reports/**` 只允许标注历史报告，不改报告事实。
- `scripts/check-docs-signoff.cjs` 仅限修复规则实现，不改变签名要求。

**明确不允许修改的范围**

- 不为满足文档而改代码。
- 不删除 still-referenced 的历史计划文档；先加状态标记：`active`、`superseded`、`historical`。
- 不改 `docs/reports/*.json` 的历史数据。

**验证方式**

- `node scripts/check-docs-signoff.cjs --strict`
- `rg -n "localhost:8000|/api/v1/sandbox/runs|npm run dev|pip install fastapi|dashboard|cost/by-team" README.md docs`
- 用 `rg -n "^@router\\.|^@app\\." src/backend -g "*.py"` 对 README API 表进行抽样核对。

**风险点**

- `docs/全局重构todos.md` 体量很大，既有计划和真实代码混在一起，贸然删会丢上下文。
- README 中存在已过时启动方式、API 路径和端口示例。
- 文档签名 strict 当前失败较多，批量补签会产生大 diff。

**完成标准**

- 所有 `docs/` plan/todos 文档满足签名规则，或明确记录豁免名单。
- README 的启动方式与 `start.ps1`、`start.sh`、`vite.config.mjs` 一致。
- README API 表不再列明显不存在或前缀错误的端点。
- 重复文档有状态标记和唯一推荐入口。

**建议的 commit 粒度**

- commit 1：补文档状态标记和签名。
- commit 2：修 README 启动/构建/测试说明。
- commit 3：修 README API 和项目结构表。

## Phase 4：测试分层与已知失败修复

**阶段目标**

- 把测试拆成可维护的层级：纯单元、后端集成、前端单测、活服务 E2E、Docker/外部依赖。
- 修复与真实代码漂移的测试，避免测试继续引用已删除或改名符号。

**允许修改的范围**

- `tests/**`、`src/backend/tests/**`、`src/frontend/__tests__/**`。
- `pyproject.toml` pytest markers。
- `package.json` scripts。
- `scripts/*smoke*`、`scripts/local_acceptance.sh`、`scripts/verify_v4_local.sh`。

**明确不允许修改的范围**

- 不为了让测试通过而降低业务逻辑。
- 不把失败测试简单 skip，除非标注为活服务、外部服务或 Docker 依赖。
- 不修改 `config/model_pool.json` 或真实 token 文件来适配测试。

**验证方式**

- `.\venv\Scripts\python.exe -m pytest -q tests src/backend/tests --collect-only`
- `.\venv\Scripts\python.exe -m pytest -q -m "not e2e and not docker"`
- `npx vitest run`
- 针对已知漂移测试：`src/backend/tests/test_task_runtime_model_binding.py`

**风险点**

- 部分测试依赖全局单例，如 `agents.api._team_manager`、`_te`、`_task_engine`。
- 测试可能写入真实 `storage/` 或 `config/`，需要临时目录隔离。
- `test_task_runtime_model_binding.py` 当前引用 `_harness_provider_credentials`、`_complete_session_with_llm_degraded_output`、`_build_agent_loop_prompt_and_system`、`agent_capability_profile` 等疑似已不存在符号。

**完成标准**

- 测试命令按层级可运行，已知失败有 marker 和说明。
- 单元测试不依赖正在运行的 `localhost:8080`。
- 测试不修改真实配置和真实运行数据。

**建议的 commit 粒度**

- commit 1：测试 marker 和脚本分层。
- commit 2：修复已知漂移测试。
- commit 3：测试隔离真实配置和 storage。

## Phase 5：API 路由收口，拆分 `agents/api.py` 巨石

**阶段目标**

- 降低 `src/backend/agents/api.py` 的 7000+ 行复杂度。
- 按职责拆出模型配置、任务、工作区、知识库、LLM、技能库等路由，同时保持外部 URL 不变。

**允许修改的范围**

- `src/backend/agents/api.py`。
- 新增 `src/backend/agents/*_routes.py` 或 `src/backend/agents/routes/**`。
- 与路由初始化相关的 `src/backend/main.py`，仅限 include_router 和依赖注入。
- 对应后端测试。

**明确不允许修改的范围**

- 不改变已有 `/api/v1/agent-config/**` URL、请求体和响应字段。
- 不改变 `TeamManager` 持久化格式。
- 不移动核心数据模型：`models.py`、`team_store.py`。
- 不同时重构前端调用。

**验证方式**

- `.\venv\Scripts\python.exe -m compileall -q src/backend`
- `.\venv\Scripts\python.exe -m pytest -q src/backend/tests/test_core_api_smoke.py src/backend/tests/test_api_integration_extended.py`
- 启动后访问 `/docs`，确认拆分后路由仍出现在 OpenAPI。
- `rg -n "/api/v1/agent-config" src/frontend src/backend/tests tests`

**风险点**

- 多处模块直接 import `agents.api` 私有全局变量，如 `_team_manager`、`_te`、`_dt_state`。
- `main.py` 启动期间注入顺序复杂，拆分时容易产生循环 import。
- 前端依赖大量隐式字段，不能只看后端测试。

**完成标准**

- `agents/api.py` 明显缩小，保留聚合入口和兼容导出。
- 拆出的路由有独立测试覆盖。
- 所有既有前端调用路径不变。

**建议的 commit 粒度**

- commit 1：抽 LLM/model provider 路由。
- commit 2：抽 workspace/knowledge-base 路由。
- commit 3：抽 task/session/runtime 路由。
- commit 4：删除仅因拆分产生的死导入。

## Phase 6：成本/Token/Legacy OpenCost 语义收口

**阶段目标**

- 解决“成本=Token”与 legacy OpenCost/Terraform 成本逻辑混杂的问题。
- 让主路径使用 TokenLedger，OpenCost 和 Terraform 明确降为 legacy/infra 侧路。

**允许修改的范围**

- `src/backend/agents/cost_routes.py`
- `src/backend/agents/token_ledger.py`
- `src/backend/agents/token_gate_routes.py`
- `src/backend/agents/cost_gate_routes.py`
- `src/backend/agents/cost_aggregator.py`
- `src/frontend/js/cost-dashboard.js`
- `src/frontend/cost-dashboard.html`
- 相关 docs 和测试。

**明确不允许修改的范围**

- 不删除 `cost_policy.py`、`ci_cost_gate.py`、Terraform legacy API。
- 不改 Token 账本 SQLite schema，除非先写迁移和回滚。
- 不改 LLM 调用记账路径：`chat_harness.py`、`budget/store.py`，除非本阶段明确覆盖并加回归。

**验证方式**

- `.\venv\Scripts\python.exe -m pytest -q src/backend/tests/test_cost_gate.py src/backend/tests/test_cost_monitor.py tests/test_sustainability.py`
- `npx vitest run src/frontend/__tests__/cost-dashboard.test.js`
- 后端启动后验证 `/api/v1/cost/summary?source=token`、`/api/v1/cost/tokens/overview`、`/api/v1/cost-gate/token/health`。
- `rg -n "OpenCost|Terraform|cost/by-team|source=infra" src/frontend/js/cost-dashboard.js README.md docs`

**风险点**

- `cost-dashboard.js` 仍可能调用 `/api/v1/cost/by-team`、`/cost/trends`、`/cost/pods` 这类 OpenCost 路径。
- README 和 docs 中已写“Token 北极星”，但代码仍保留 legacy 入口，容易产生认知冲突。
- 真实 usage 数据可能 team_id 为空，需要标注“未归因”而不是静默丢弃。

**完成标准**

- 成本页默认所有主卡片来自 TokenLedger。
- Infra/OpenCost 入口有明确 UI 或 API 标识，不再冒充主成本。
- Token Gate 和 Terraform Gate 文档、路由、前端入口清晰分离。

**建议的 commit 粒度**

- commit 1：后端 API 语义和返回字段收口。
- commit 2：前端成本页数据源收口。
- commit 3：legacy 文档和测试补齐。

## Phase 7：前端巨型页面模块化

**阶段目标**

- 拆解 `skill-extract.js`、`digital-twin-cli.js`、`plaza.js`、`cost-dashboard.js` 等巨型脚本。
- 保持页面功能不变，先拆模块边界，再做 UI 或行为优化。

**允许修改的范围**

- `src/frontend/js/**`
- `src/frontend/__tests__/**`
- 对应 HTML 中 `<script type="module">` 或脚本加载顺序。
- `vite.config.mjs` 仅限新增入口或 chunk 配置。

**明确不允许修改的范围**

- 不改后端 API。
- 不改视觉设计和交互流程。
- 不把全局对象一次性删除，例如 `window.AG`、legacy aliases、页面内联调用函数。

**验证方式**

- `npx vitest run`
- `npm run build`
- 浏览器冒烟：`/agent-team-config.html`、`/plaza.html`、`/skill-extract.html`、`/digital-twin-cli.html`、`/cost-dashboard.html`。
- `rg -n "window\\.|onclick=|data-i18n|legacy|AG\\." src/frontend`

**风险点**

- 多页面依赖全局函数和内联 `onclick`。
- Vitest 可能只覆盖 helper，不覆盖真实 DOM 加载顺序。
- Three.js/digital twin 模块加载顺序易受拆分影响。

**完成标准**

- 每个巨型脚本拆出稳定模块，单文件行数显著下降。
- 页面全局兼容层保留，老 HTML 入口不破。
- 前端测试和构建通过。

**建议的 commit 粒度**

- commit 1：抽公共 API/client/toast/state helpers。
- commit 2：拆 `cost-dashboard.js`。
- commit 3：拆 `plaza.js`。
- commit 4：拆 `skill-extract.js`。
- commit 5：拆 digital twin 相关脚本。

## Phase 8：核心运行时硬化与删除候选确认

**阶段目标**

- 在前面阶段已有验证保护后，再处理核心路径重构、死代码删除和兼容层收口。
- 明确哪些 legacy 入口保留、哪些进入 deprecation、哪些可以删除。

**允许修改的范围**

- `src/backend/agents/chat_harness.py`
- `src/backend/agents/plaza_engine.py`
- `src/backend/sandbox/orchestrator.py`
- `src/backend/sandbox/twin_loop.py`
- `src/backend/channels/**`
- `src/backend/agents/*legacy*` 或已标记 deprecated 的入口。
- 对应测试和文档。

**明确不允许修改的范围**

- 不一次性删除 public API。
- 不改变默认模型解析、全局模型 override、token 归因行为。
- 不改持久化数据结构，除非带迁移脚本和回滚说明。
- 不删除 `ponytail/`、`datacenter_api.py`、`channels/**` 等看似边缘但可能被页面或文档引用的模块，需先做引用清单。

**验证方式**

- 全量可用测试层级：后端单元、前端 Vitest、构建、核心 smoke。
- 活服务 smoke：启动 `.\start.ps1`，检查 `/api/v1/health`、`/api/v1/agent-config/llm/test-model`、主要页面。
- 删除候选必须先跑 `rg` 引用检查和 OpenAPI 路由对比。

**风险点**

- `chat_harness.py` 是 LLM 调用、token 记账、fallback、全局模型 override 的交汇点。
- `plaza_engine.py` 与 `plaza_routes.py` 涉及 SSE、任务派发、fallback 计划。
- `sandbox` 与 `trial_api` 存在演练、技能进化、棘轮写回链路，删除兼容字段会破坏旧数据。

**完成标准**

- 每个删除项都有引用检查、替代路径和测试证明。
- Deprecated 清单进入 README 或 docs，包含下线条件。
- 核心路径回归通过，启动和关键 API 正常。

**建议的 commit 粒度**

- commit 1：标记 deprecation 和兼容策略。
- commit 2：硬化 `chat_harness` 错误边界和模型解析。
- commit 3：硬化 plaza fallback/任务派发路径。
- commit 4：硬化 sandbox/trial 兼容加载。
- commit 5：删除已验证无引用的 legacy 代码。
