# 统一 3D 办公室场景设计（P7）· v2

> 状态：current design（v2，按 Owner 提供的 Marvis 办公室参考图校准）。对应 Todos P7 节。
> **全站只有两个 3D 场景：① 极简办公室（一切任务与孪生都在这里发生）② 隐藏款枯山水休息区。** 不做圆桌议事厅，不做六分区大场景。四套旧 three.js 实现（约 1 万行）合并为一套引擎。

## 1. 视觉基调（参考图规范）

对标 Marvis 办公室风格：**极简白 + 等轴测视角 + 软阴影**。

- 环境：纯白/浅灰空间，无墙面贴图，家具白色系（桌、椅、柜、茶水吧、咖啡机），软投影落地。
- Agent 造型：**采用 plaza.js 现有 Agent 模型骨架，皮肤替换为本项目自有造型**——深色小兽形角色，**项圈颜色 = 角色/团队标识**（参考图：Marvis 红圈、File Agent 紫圈、青圈）。头顶浮动名牌。
- 状态用「道具语言」而非图标：坐工位屏幕亮 = 执行中；跑步机 = 后台长任务处理中；茶水吧端咖啡 = 等待依赖/排队；卫生间等趣味位 = 短暂离线（保留参考图的幽默感）。
- **那只猫保留**：自由漫游的彩蛋生物，无任何业务含义，会踩过键盘、蹭空闲 Agent。
- 指标（今日消耗/节省 Token、对话明细、任务计数）：**不进 3D**，放右侧 HTML 面板（同参考图布局），3D 只负责空间与状态叙事。

## 2. 设计原则

1. **一个办公室承载全部业务**：不按域造分区大厅，办公室里的家具/角落即功能位。
2. **生产/孪生双视觉层**：孪生演练与竞标发生在**同一个办公室的镜像层**——低饱和/线框化/半透明 + 视口角标「SIMULATION」；竞标多候选用画中画小视口并排（同一 scene 多 viewport 渲染，不是多场景）。用户永远一眼分清真实与仿真。
3. **位置状态单一数据源**：OfficeState store + 纯函数 reducer，SSE/WS 事件驱动，场景是 store 的渲染投影；`window.S.positions` 等旧变量降级为只读派生视图。
4. **渐进迁移可回退**：feature flag `?office3d=1` 灰度，旧页面保留至对应阶段验收后归档（不硬删）。

## 3. 办公室布局（家具即功能）

```
 ┌────────────────────────────────────────────────┐
 │  茶水吧(咖啡机/杯子)        技能架(知识库,水晶陈列) │
 │                                                │
 │  跑步机×N        工位网格 (每 Agent 一桌一椅一屏)   │
 │  (后台任务)       ┌─┐ ┌─┐ ┌─┐                    │
 │                  └─┘ └─┘ └─┘     🐈(自由漫游)    │
 │  白板讨论角        ┌─┐ ┌─┐ ┌─┐                    │
 │  (Plaza站立会议)   └─┘ └─┘ └─┘                    │
 │                                    [趣味角落]    │
 └────────────────────────────────────────────────┘
          (隐藏门 → 枯山水庭院，独立第二场景)
```

| 功能位 | 承载业务 | 交互/动画 |
| --- | --- | --- |
| **工位网格** | 生产任务执行。每个在编 Agent 一张桌；执行中屏幕亮蓝、键盘敲击动画；协作 = 工位间飞出的有向光线（P5-5 工作流边可视化） | 点击桌子 → 右侧面板显示该 Agent 当前任务/会话/token |
| **白板讨论角** | Plaza 讨论（**无圆桌**）：讨论开始时参与 Agent 起身走到白板前站立围拢，发言者头顶气泡+高亮，moderator 持笔在白板上逐条写要点（写的就是结构化主张/计划步骤，P6-4/P5-1 的可视化），用户插话显示为白板旁弹出的用户头像气泡 | 点击白板 → 打开讨论时间线/执行计划面板 |
| **技能架** | 技能库：墙边陈列架，水晶按类目排列，命中率高的更亮；Agent 领技能走到架前取用；SkillClaw 萃取 = 架旁小工作台的打磨动画 | 点击水晶 → 技能详情 |
| **跑步机** | 长时后台任务（提取/演进/批处理）：负责的 Agent 在跑步机上跑，速度≈进度 | 悬停显示任务进度 |
| **茶水吧 / 趣味位** | 等待与空闲的状态语言；空闲过久的 Agent 端咖啡、逗猫 | 无业务操作，纯叙事 |
| **镜像层（孪生）** | 演练/竞标：整个办公室切入镜像视觉，或右下画中画 N 个小视口并排跑竞标候选（同一批桌椅、不同团队/技能/协作组合），每个视口浮动 (评分, token) 徽标，胜者视口高亮后「转正」渲染回生产层 | 点击视口 → 该候选的试炼详情 |
| **隐藏门 → 枯山水** | Owner 专属彩蛋：Logo 连点 5 次或键入 `zen`，相机穿过隐藏门进入**第二场景**——`digital-twin-cli-3d.js:700` 的「现代发光枯山水（致敬龙安寺）」**几何/材质/缘侧坐姿原样整体迁移**；UI 全部淡出，空闲超阈值的 Agent 会自己溜达进来坐缘侧 | 全系统唯一无指标、无任务、不谈效率之地 |

叙事闭环在一个房间里完成：**白板前讨论出计划 → 镜像层/画中画竞标选出最省 token 的组合 → 胜出者回到工位执行 → 右侧面板滚动消耗 → 技能架多一颗新水晶**。

## 4. 状态模型与模块架构（沿用 v1，缩编）

```js
OfficeState = {
  agents: { [id]: { station, activity: 'working'|'meeting'|'treadmill'|'coffee'|'idle'|'zen',
                    collar, layer: 'prod'|'mirror' } },
  desks:   { [deskId]: { agentId, screenOn } },
  meeting: { active, speakerId, boardLines[] },          // 白板讨论角
  edges:   [ { from, to, kind, ttl } ],                  // 协作光线
  trials:  [ { viewportId, combo, score, tokens } ],     // 竞标画中画
  skills:  { [id]: { luster, hits } },
  cat:     { pos, mood },                                 // 🐈
}
```

```
js/office/
  office-engine.js   // 唯一 Scene + 主视口 + 竞标画中画 viewports
  office-state.js    // store/reducer + 旧变量只读 shim
  office-nav.js      // 等轴测相机、聚焦、zen 彩蛋入口
  adapters/          // plaza-sse / sandbox-sse / skill-ws / tasks-poll
  props/             // desk, whiteboard, shelf, treadmill, bar, cat, agent-figure
  zen-garden.js      // 第二场景：枯山水（从 digital-twin-cli-3d 整体搬移）
```

技术约束：three 单版本钉死；Agent/水晶 InstancedMesh；60fps@50 Agent；竞标视口用粗模+降采样；掉帧自动关阴影。

## 6. 风险

- 单房间信息密度：50+ Agent 时工位网格自动扩展/分组折叠（按团队分岛）。
- 讨论角与工位动线冲突：讨论聚拢时工位保留占位影子，避免「人去桌空」的困惑。
- 镜像层语义混淆为硬性验收项：任何「分不清真实/仿真」反馈按 bug 处理。
- 枯山水是 Owner 钦点保留项：迁移时逐 mesh 对照，不允许「重写等效」，必须原样搬移。
