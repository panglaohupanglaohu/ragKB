## 0. 演示故事设定

### 0.1 场景

北美 AI 搜索项目的生产 ElasticSearch/OpenSearch 集群在促销前出现查询延迟上升。业务希望从 `r6g.large` 扩到 `r6g.xlarge`，同时评估是否增加数据节点。约束如下：

- 变更窗口只有 90 分钟。
- 北美 AI 项目涉及数据驻留和审计要求。
- 成本团队要求说明 RI/Savings Plan 影响。
- 运维团队必须先在数字孪生中演练，覆盖自动化、单步、故障注入、回滚和监控验证。
- 最后要把过程沉淀成技能，并让系统演进机制把发现的问题推进到治理闭环。

### 0.2 本次演示要证明什么

- 系统能从“人类描述的组织结构”落到“可操作团队和成员”。
- 议事厅不只是聊天，而是能生成计划、拆任务、打开验证队列、进入技能萃取和成本治理。
- 技能不是一次性文本，而是能经历萃取、补全、验证、演化、发布、注入。
- 数字孪生不只是播放动画，而是能创建试炼、分支对比、注入故障、评分、抽 SOP、反哺团队。
- 系统演进不是后台报表，而是能把讨论、任务、试炼的证据转成演进项，并通过棘轮机制锁定改进。
- 成本治理能把 token、团队、服务成本连接到任务、议事厅和 Cost Gate。

### 1.4 单队原则

这套演示只有一个 AWS 运维团队，团队里面有多个成员。不要为 Leader、架构师、成本优化、北美运维分别建团队，也不要每次演示都新建一个带 run id 的 AWS 团队。

推荐结构：

- 团队：`AWS 运维团队`
- 成员：运维 Leader、上云架构师、运维操作员、巡检监控员、成本优化成员、北美 AI 项目运维员
- Demo ID：只放在议事厅、讨论、任务、技能萃取标题、报告里

如果页面里已经有历史测试团队，例如 `AWS 运维团队 aws_ops_e2e_...`，应先删除这些历史团队，只保留一支正式演示团队。自动化脚本已经改为默认清理这些历史团队，并复用单个 `AWS 运维团队`。

## 2. 第一幕：创建或复用 AWS 运维团队

页面：`/agent-team-config.html`

### 2.1 创建或复用团队

操作：

1. 先在团队下拉框中查找是否已有 `AWS 运维团队`。
2. 如果已有，直接选择它，不要新建第二支 AWS 运维团队。
3. 如果没有，再点击“创建新团队”。
4. 团队名称填写：`AWS 运维团队`
5. 描述填写：

```text
负责北美 AI 搜索项目的 AWS ElasticSearch/OpenSearch 运维。覆盖容量规划、资源创建、监控巡检、故障恢复、成本优化、合规部署、自动化脚本评审和演练复盘。
```

通过标准：

- 团队选择列表里只保留一支 AWS 运维团队。
- 团队总览里能看到 `agent_count`、模型数、任务数等卡片。

### 2.2 添加六类成员

进入新团队后，用“新建智能体”或向导逐个创建成员。

| 成员 | 角色描述 | 演示重点 |
| --- | --- | --- |
| 运维 Leader | 负责整体协调、任务派发、风险升级、变更窗口把关 | 后续作为议事厅主持人 |
| 上云架构师 | 负责 AWS/OpenSearch 容量规划、网络、AZ、实例族选择 | 产出扩容策略 |
| 运维操作员 | 负责 Terraform/脚本执行、资源创建、变更落地 | 接收 Build System 脚本 |
| 巡检监控员 | 负责指标巡检、告警、故障定位、回滚触发 | 设计监控和回滚门槛 |
| 成本优化成员 | 负责账单、RI/Savings Plan、预算影响、成本治理目标 | 接入成本工作台 |
| 北美 AI 项目运维员 | 负责北美部署、数据驻留、审计、区域法规约束 | 接收特质技能 |

每个成员建议填写系统提示词：

```text
你是 AWS 运维团队的[角色名]。本次任务围绕北美 AI 搜索项目的 ElasticSearch/OpenSearch 资源伸缩。回答必须覆盖稳定性、成本、合规、自动化和可回滚验证。不能只给概念，必须给可执行动作、风险和证据。
```

通过标准：

- 团队中有 6 个成员。
- 每个成员的角色、描述、系统提示词不为空。
- 至少 Leader、架构师、操作员、监控员、成本成员、北美成员能在列表中被区分。

### 2.3 绑定模型、工具、技能

操作：

1. 在团队模型池中确认默认模型可用。
2. 在“工具”页启用以下类别工具，名称不必完全一致，关键词匹配即可：
   - shell/code/runtime
   - file/read/write
   - terraform/aws/cloud
   - monitor/alert
   - cost/billing
   - task/delegate
   - skill/manage
3. 在“技能”页启用以下能力：
   - 变更计划
   - Terraform 脚本编写
   - 代码 review
   - 监控回滚
   - 成本优化
   - 合规检查
4. 打开“技能三池”或类似区域，观察“特有 / 通用 / 储备”分类。

通过标准：

- 团队工具和技能列表非空。
- 成本优化成员至少拥有成本相关能力。
- 北美 AI 项目运维员至少拥有合规/区域部署相关能力。
- 能触发“重新分类”并看到三池数量变化或保持稳定。

创意演示点：

- 把团队看成一个“变更指挥中心”，不是六个普通 agent。
- Leader 管派发，架构师管设计，操作员管执行，监控员管安全刹车，成本成员管预算刹车，北美成员管合规刹车。

## 3. 第二幕：议事厅形成 ElasticSearch 伸缩计划

页面：`/plaza.html`

### 3.1 创建议事厅

操作：

1. 点击“创建广场/议事厅”。
2. 名称：`北美 AI 搜索伸缩议事厅 AWS-DEMO-YYYYMMDD-HHMM`
3. 描述：

```text
围绕北美 AI 搜索项目 ElasticSearch/OpenSearch 伸缩进行跨角色决策。目标是形成可派发计划、可执行脚本需求、技能萃取材料、数字孪生演练目标和成本治理输入。
```

4. 选择刚才的 AWS 运维团队成员作为参与者。
5. 指定运维 Leader 为主持/议事长。

通过标准：

- 左侧广场列表出现新议事厅。
- 进入后能看到参与成员或 3D 议事场景。

### 3.2 创建讨论

点击“新建讨论”，填写：

标题：

```text
ElasticSearch/OpenSearch 实例资源伸缩：北美 AI 搜索项目
```

目标：

```text
形成一份可派发的执行计划，要求 Build System 团队编写运维脚本，AWS 运维团队负责评审、演练、执行、监控、回滚、成本治理和北美合规验证。
```

描述：

```text
当前集群为 3 个 r6g.large 数据节点，P95 查询延迟升至 450ms，促销窗口预计 QPS 增长 2.3 倍。候选方案包括升级为 r6g.xlarge、增加数据节点、调整分片、副本、冷热层策略。必须覆盖 Terraform plan、变更窗口、自动化脚本、CloudWatch/OpenSearch 指标、故障注入、回滚条件、RI/Savings Plan、北美数据驻留和审计证据。
```

通过标准：

- 讨论出现在讨论列表。
- 讨论状态为 open 或可开始。

### 3.3 启动讨论并观察多角色协作

操作：

1. 选中讨论。
2. 点击“开始”。
3. 观察消息流、状态文字和最终执行计划。

你应该重点观察：

- Leader 是否把任务分给不同角色。
- 架构师是否给出容量和实例族选择。
- 操作员是否关注 Terraform/脚本步骤。
- 监控员是否给出指标和回滚阈值。
- 成本成员是否指出 RI/Savings Plan 或预算影响。
- 北美成员是否提出区域、数据驻留、审计约束。
- 计划面板是否出现“执行计划”。

通过标准：

- 消息流非空。
- 计划面板非空。
- 计划里至少包含“容量评估、脚本、监控、成本、合规、回滚”六类内容。

异常观察：

- 如果讨论结束但计划为空，说明 LLM 输出解析或计划兜底有问题。
- 如果按钮停在“进行中/总结中”太久，记录 discussion id 和页面状态。

### 3.4 对计划做三路分流

在计划面板中依次操作：

1. 选择目标团队为 `build_system` 或 Build System 团队。
2. 点击“派发”或“智能拆解”。
3. 点击“拆解并执行”，如果你想展示任务运行链路。
4. 点击“成本治理”，把讨论输入带到成本工作台。
5. 对已关闭讨论点击“萃取”，跳转到技能萃取页。
6. 可选：点击“修订执行计划”，观察计划是否重写。
7. 可选：点击“根据此话题继续深入讨论”，创建一个二级讨论，例如“分片重平衡风险”。

通过标准：

- 智能拆解后应出现任务列表或 task_count。
- 成本治理跳转时 URL 或页面 banner 应带有 plaza/discussion 来源。
- 技能萃取跳转时 source_text 应自动带入讨论计划。
- 验证队列面板能刷新，或能显示当前没有验证项。

创意演示点：

- 这里展示的是“同一份结论的多出口”：派发给团队、沉淀为技能、送入成本、变成演进证据。

## 5. 第四幕：技能萃取、补全、验证、演化、注入

页面：`/skill-extract.html`

### 5.1 从议事厅跳转萃取

推荐路径：

1. 回到 `/plaza.html`。
2. 选择刚才讨论。
3. 如果讨论已关闭，点击“萃取”。
4. 到 `/skill-extract.html` 后确认 source 区域带入了讨论计划。

兜底路径：

直接打开 `/skill-extract.html`，粘贴以下材料：

```text
AWS-DEMO ElasticSearch/OpenSearch 伸缩复盘材料：
1. 先根据 P95 延迟、CPU、JVM heap、segment count、threadpool rejected、磁盘水位判断瓶颈。
2. 架构师比较升级实例规格、增加数据节点、调整分片副本三种方案，并给出成本和风险。
3. 运维操作员用 Terraform plan 生成变更，脚本必须支持 dry-run、apply、rollback。
4. 监控员在变更前后采集 CloudWatch 与 OpenSearch 指标，设置 P95、heap、磁盘、rejected、cluster health 门禁。
5. 成本成员计算 r6g.large 到 r6g.xlarge 的月成本差异，并检查 RI/Savings Plan 覆盖率。
6. 北美 AI 运维员检查 region、数据驻留、审计日志和合规审批。
7. 失败时先冻结写入或降低副本调整速度，再执行回滚，并把证据写入任务 trace 和演进项。
```

操作：

通过标准：

- 候选名称不应都叫“新技能”，应能区分容量评估、脚本执行、监控回滚、成本合规等能力。
- LLM 不可用时，系统应明确标记需要 LLM review，而不应把低质量草稿直接标为高置信 ready。
